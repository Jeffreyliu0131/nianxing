# 念行：首版产品需求

## 结论

首版只解决一个核心问题：让用户在念头消失前完成记录，并立刻知道它应该进入行动时间线还是灵感库。成功标准是从打开应用到保存内容不超过三个动作，断网时仍能完成整个记录流程。

## 用户与场景

主要用户是同时处理工作、学习和个人项目，容易拖延或忘记后续安排的个人用户。

- 临时想到明天或之后要做的事，希望直接说一句话完成安排。
- 突然出现产品想法、问题或学习主题，希望先可靠保存，之后再整理。
- 面对较多待办时，希望看清今天的时间顺序与明天的重点，降低启动成本。

## 产品结构

### 行动时间线

- 默认显示今天的时间顺序与明天预览。
- 任务包含标题、计划时间、预计时长、状态、备注与来源。
- 支持完成、编辑、删除。

### 灵感库

- 保存尚未承诺时间的想法、问题和学习主题。
- 支持按“全部、想法、学习”筛选。
- 支持把灵感编辑后继续保留，或通过统一输入创建带时间的行动。

### 统一捕捉

- 支持文字与浏览器可用时的语音转写。
- 输入可由 DeepSeek 整理为一个或多个结构化条目。
- 模型不可用时使用本地规则整理，用户始终先看到预览再保存。

## 首版验收标准

- 应用可通过 Web App Manifest 安装，并在生产构建中注册 Service Worker。
- 首次加载后，断网仍可打开应用、查看已有内容、创建和修改记录。
- 一句话可以生成任务、想法或学习条目；带“明天、后天、下午、晚上”等表达时能解析基础时间。
- DeepSeek API Key 不出现在浏览器代码、网络请求配置或本地存储中。
- AI 请求失败、超时或未配置时自动降级到本地整理，并明确标注来源。
- 登录后，任务与灵感自动同步到 Sites D1；不同登录用户的数据互相不可见。
- 离线修改恢复网络后自动上传；并发修改不得静默覆盖，删除记录不得因旧设备同步而复活。
- 核心交互在 iPhone 与 Android 预览尺寸中可完成，底部输入不遮挡内容。

## 首版明确不做

- 自建账号密码系统、多人共享编辑。
- 完整日历替代、复杂重复任务、第三方日历双向同步。
- 后台定时推送；浏览器通知需要单独的权限、服务端调度与平台验证。
- 自动执行模型建议。所有新增内容都由用户确认后落库。

## 当前收敛与验收（2026-09-05）

用户已批准以可靠捕捉和人工确认作为主任务。访客、旧未标归属数据和每个稳定账号的本地空间分开；不自动迁入。服务器 PUT 必须同时满足登录身份、预期账号 ID 和 revision。401 或账号变化触发重新确认，旧请求不能写入新账号。已挂载账号支持离线编辑；离线重载进入访客空间，避免未经确认展示上一个账号。

删除后在本次会话支持撤销，使用晚于墓碑的更新时间恢复；账号切换不会带走撤销记录。保护运行时的 App/Worker 变更是本次账号修复的必要范围，已重新生成完整性锁，检查器继续启用。

后续优先级：先运行 README 中的捕捉/确认/恢复验证，再决定其他能力。灵感转项目、任务拆分、日历、提醒与供应商扩展暂不开发。真实用户留存、时钟偏差下冲突语义与生产身份切换仍须现场验证。

## 2026-09-07 确认与保存一致性

任务可保留 `scheduledAt: null`，在“待安排”中可编辑、完成或删除；清空已排期任务的时间也能回到待安排。旧有效日期保持原值，不反向推断用户当时是否指定。未知时长不补成 30 分钟，不计入已估时长。

“周天”与“周日”使用同一规则。只给日期或时段时，本地仍给出建议时刻（如下午 14:00），确认页明确标为建议并允许清空。确认页展示原始输入、标题、类型、时间、时长、备注和标签；保存不再补入未展示的安排。整理过程绑定输入版本，保存旧结果不会清掉期间新写的输入，取消确认保留输入。

验证通过：构建与运行时完整性、6 项领域/存储测试、9 项 Worker 测试、11 项 Playwright 回归。390px 确认页和待安排列表已检查；覆盖日期同义表达、本地/云端往返、旧记录兼容、延迟整理时新输入保留、取消、排期和删除恢复。点击提交/保存时保留输入焦点直到操作完成，避免键盘收起移动按钮造成首次点击落空。仅合成输入和替身，没有真实模型或站点部署。
